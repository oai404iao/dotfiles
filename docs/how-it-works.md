# How the configuration works

Chezmoi combines source files with non-secret machine data and external secret
references to compute destination files. Applications then maintain their own
runtime state outside the source tree.

```text
Git source + machine data + secret references
    -> chezmoi render / create / modify
    -> reviewed target files under $HOME
    -> application-owned state, caches, and sessions
```

## Source and destination

Run repository commands from `~/.local/share/chezmoi`, or locate the source with
`chezmoi source-path`. Source filenames encode destination behavior; a file
under `dot_config/` is not deployed with that literal directory name.

| Source | Responsibility |
|---|---|
| `.chezmoi.toml.tmpl` | Initializes machine data and secret backends |
| `.chezmoiignore` | Selects capability-dependent targets and excludes local state |
| `.chezmoiexternal.toml` | Declares pinned Zsh archives and fetched global Pi instructions |
| `.chezmoiremove` | Retires specific old nvm loader files |
| `.chezmoitemplates/` | Shared Niri output and binding definitions |
| `dot_config/` | Application configuration |
| `private_dot_ssh/` | Generic SSH policy and encrypted public selectors/host metadata |
| `dot_local/` | User commands and desktop integration |
| `scripts/`, `tests/`, `docs/` | Source-only helpers, checks, and operating guides |

Both READMEs and `AGENTS.md` are source-only too. These paths must remain
excluded by `.chezmoiignore`.

## Source attributes

| Pattern | Destination behavior |
|---|---|
| `dot_name` | Writes `.name` |
| `private_name` | Uses private permissions |
| `executable_name` | Sets executable mode |
| `create_name` | Creates only if the target does not exist |
| `modify_name` | Transforms existing content read from stdin |
| `name.tmpl` | Renders a Go template |
| `encrypted_name.age` | Decrypts a native encrypted source |
| `run_once_before_*` | Runs once before target updates |

Attributes can be combined. Before renaming a source, verify its mapping with
`chezmoi target-path <source-path>` and inspect the explicit target's status.
Changing an attribute can change ownership or permissions, not just spelling.

## Decide who owns a file

| Data | Owner |
|---|---|
| Reproducible settings, templates, versions, public recipients, secret references | Git |
| Model/Telegram credentials, SSH private keys, backed-up age identity | Bitwarden through `rbw` |
| Static SSH/Git identity metadata that needs versioning | age-encrypted source |
| Sessions, credentials retained by modifiers, trust, histories, caches, databases | Machine/application |
| Downloaded plugins, runtimes, skills, and package installation state | Their installer or separate source repository |

Before importing a file, classify it as declarative configuration, generated
state, mutable state, or secret material. Only declarative configuration is a
normal overwrite-managed target. Use precise ignores for mutable state and an
appropriate secret backend for credentials.

## Seeds and modifiers

`create_` files give Matugen, Waypaper, and other generators a usable initial
value. A later apply must not overwrite the value generated by the application.
In DMS mode, `create_empty_` Niri fragments also preserve intentionally empty
files required by the include graph.

`modify_` sources merge declared settings while preserving fields owned by the
application. Examples include DMS preferences, Pi settings/authentication,
Tether Bluetooth policy, and approved pnpm builds. Read each modifier's contract
before changing which keys it replaces; preserving unknown keys is part of
the interface, not incidental implementation.

## Ignoring is not removal

Turning off a capability usually stops managing its targets. It does not
delete previously rendered files, disable an enabled service, or erase saved
credentials. Follow the component's migration procedure before switching profiles.

Ignored files can contain the only recovery copy. Never use broad Git cleanup
to make this configuration repository look clean.

Continue with [machine configuration](configuration.md) or the
[daily workflow](usage.md). Review [security](security.md) before any preview
that might include existing credentials.
